# ADR-0009: `doh` カテゴリだけは保護者でも解除できないようにする

- 状態: 採用（2026-08-15 の UI 実機確認で発見・同日承認）
- 日付: 2026-08-15

## 文脈

ADR-0005 は `forced_block_categories`（3 段目）を **MVP では空**にし、
「保護者はすべて解除できる」を要件として固定した。一方 ADR-0007 は DoH プロバイダを
`doh` カテゴリで BLOCK することにした。

この 2 つが噛み合っていない。`doh` の BLOCK は **7 段目**のカテゴリ別ルールであり、
**4 段目**の保護者の許可に負ける。つまり保護者が `use-application-dns.net` を
許可リストに入れると、Firefox の DoH が復活して DNS フィルターが素通りになる。

Step 9 の UI 実機確認で、これが事故として起きやすい形になっていることが分かった。
「遮断された記録」画面は近い時刻の遮断をまとめて表示し、**既定で全件にチェックが
入った状態**で「選んだ N 件を許可」ボタンを出す。ページが表示されないときに保護者が
押す動線そのもので、そこに `use-application-dns.net` が混ざる。

押した結果は「フィルターが素通りになる」だが、画面には何も起きない。UI は
「フィルター稼働中」と表示し続け、判定履歴も減るだけで異常には見えない。
CLAUDE.md が最も避けるべきとしている「効いているつもりで素通り」に一致する。

## 決定

**`doh` を全プロファイルの `forced_block_categories` に入れる。**
保護者の許可リストでは解除できなくする。例外はこのカテゴリだけで、
`adult` や `gambling` は従来どおり保護者が解除できる。

### なぜ `doh` だけ例外にしてよいか

他のカテゴリと**決めている対象が違う**。`adult` の解除は「そのサイトを見せるか」の
判断であり、保護者の権限の範囲にある。`doh` の解除は「フィルターが働くかどうか」の
判断であり、その 1 件を許可した瞬間に**他のすべてのカテゴリ設定が無効になる**。

保護者がフィルターを止めたい場合の経路は既にある。設定画面のフィルター停止であり、
そちらは UAC で保護され、止まっていることが画面に明示される。DoH の許可は
同じ結果を**表示のないまま**もたらすので、経路として妥当でない。

### UI 側でも既定から外す

Policy Engine で塞ぐだけでは、保護者が許可を押しても何も起きない
（＝許可したのに遮断され続ける）という分かりにくい状態になる。
「まとめて許可」の既定チェックから解除不可カテゴリを外し、理由を画面に書く。

**これは判定ロジックの二重化ではない。** 判定は Policy Engine が単独で下し、
UI は `forced_block_categories` を読んで既定値と説明を決めるだけで、
UI 独自の可否判断は持たない。

CLI の `allow` も同じ理由で警告を出す（登録は拒否しない）。
`ifilter allow use-application-dns.net` が黙って成功すると、
「許可したのに繋がらない」を保護者が自力で調べることになる。

## 却下した案

- **UI でだけ防ぐ** — CLI の `allow` や DB 直接操作では抜ける。しかも
  「UI では止まるが CLI では通る」という、判定が 2 か所にある状態になる
- **`doh` の危険度を Critical にする** — リスク上限（6 段目）も保護者の許可
  （4 段目）に負けるので解決しない。順序を変えると保護者の権限が全体的に弱まる
- **現状維持** — ADR-0007 が「MVP に必須」とした対策が、事故が起きやすい動線で
  無効化できる状態のまま残る

## 結果

- ADR-0005 の「MVP では `forced_block_categories` は空」は **`doh` のみ例外**となる。
  段の仕組み自体は変わらない（ADR-0005 が「集合に足すだけで解除不可になる」と
  設計したとおりの使い方）
- `domain-model` のテスト「強制ブロックカテゴリは MVP では空」を、
  「`doh` だけが入っている」に置き換える
- 保護者が DoH を使いたい場合は、フィルター自体を止める（設定画面）
- IP 直打ちの DoH は依然として塞げない。WFP（Step 11〜12）の担当という
  ADR-0007 の整理は変わらない
