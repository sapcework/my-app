# ADR-0003: HTTPS の MITM 復号を採用しない

- 状態: 採用
- 日付: 2026-08-14

## 文脈

ページ本文を読めば判定精度は上がる。しかしそのためには、独自ルート証明書を
子供の PC にインストールし、すべての HTTPS 通信を復号する必要がある。

## 決定

**MITM 方式は採用しない。** 暗号化を解かずに得られる情報だけで判定する。

- DNS クエリのドメイン名
- 接続先 IP / ポート（WFP）
- TLS ハンドシェイクのメタデータ

## 結果

- ページ本文に基づく細かい判定はできない。ドメイン単位の粒度が上限になる
- そのぶんを Profile・カテゴリ・未知ドメインの安全側処理（ADR-0002）で補う
- 判定材料が少ないことは、ADR-0002 の「安全と確認できたものだけ通す」方針と整合する

## 理由

1. **プライバシー** — 子供の全通信を平文で覗ける仕組みを作らない。この製品は
   ペアレンタルコントロールであり、監視ツールではない
2. **セキュリティ** — ルート証明書と秘密鍵が端末上に存在すること自体が攻撃対象になる
3. **アプリ互換性** — 証明書ピンニングを行うアプリ（銀行・一部ゲーム）が動かなくなる
4. **証明書管理** — 失効・更新の運用コストが継続的にかかる
5. **法的・運用上の問題** — 通信の秘密に触れる
6. **パフォーマンス** — 全通信の復号・再暗号化のコスト

将来 AI による本文分類を検討する場合も、MITM ではなく別の手段
（端末内のブラウザ拡張による自己申告、サーバー側のカテゴリ DB など）を先に評価する。
