# ADR-0007: DoH 対策を MVP に含める

- 状態: 採用（2026-08-14 の設計レビューで承認。指示書 40 からの変更）
- 日付: 2026-08-14

## 文脈

指示書 40 では DoH / DoT 対策を「MVP 後」に置いている。しかし DNS フィルターは、
ブラウザが DoH（DNS over HTTPS）を使った瞬間に**クエリが一切届かなくなる**。

- Firefox は DoH を既定で使う設定を持つ
- Chrome / Edge はユーザーが「セキュア DNS」を有効にできる
- どちらも子供が設定画面から数クリックで有効にできる

つまり DoH 対策が無い MVP は、「ブラウザに依存しない遮断」という
この製品の中心的な価値を満たさない。フィルターが動いているように見えて
実際には素通りしている、という最も危険な失敗の形になる。

## 決定

**最低限の DoH 対策を Phase 3（Step 8）に含める。**

1. **Firefox** — canary domain `use-application-dns.net` に NXDOMAIN を返す。
   Firefox はこの応答を受けると DoH を自動的に無効化する
2. **Chrome / Edge** — グループポリシー（レジストリ `DnsOverHttpsMode = off`）で
   無効に固定する。対象環境は Windows 11 Pro なので設定可能
3. **既知 DoH プロバイダのドメインを BLOCK** する

IP 直打ちによる DoH アクセスは DNS レイヤでは塞げないため、Phase 5 の
ユーザーモード WFP（ADR-0004）で対応する。ここは MVP のスコープ外とする。

## 結果

- MVP の受け入れテストに「DoH を有効にしたブラウザで素通りしないこと」を追加する
  （TEST_PLAN.md §5）
- 完全ではない。IP 直打ち DoH と QUIC は MVP では塞げないが、
  **設定画面から数クリックで回避できる状態は解消される**
- 「DNS が通れば安全」という設計にはしない、という指示書 23 の方針と整合する

## 指示書との差分

指示書 40 の MVP 必須リストに `DoH 最低限対策` を追加した。
2026-08-14 の設計レビューで承認済み。
