# ADR-0004: 遮断は DNS を第一段、ユーザーモード WFP を第二段とする

- 状態: 採用
- 日付: 2026-08-14

## 文脈

ブラウザ拡張は Chrome / Edge / Firefox / Brave ごとに実装が要り、
拡張を無効化されれば終わる。PC 全体の通信を対象にする必要がある。

## 決定

段階的に構える。

1. **第一段: ローカル DNS プロキシ**（Phase 3）
   UDP 53 でリッスンし、ドメイン名で判定する。実装コストが最も低く、
   全アプリ・全ブラウザに一律に効く
2. **第二段: ユーザーモード WFP**（Phase 5）
   `FwpmFilterAdd` を ALE レイヤに設定し、IP 直打ちと DoH の IP アクセスを塞ぐ
3. **カーネル callout ドライバは、必要と実証できるまで作らない**

## 結果

- 現在の開発環境（Windows SDK 10.0.26100、WDK 未インストール）で第二段まで着手できる。
  カーネルドライバに進む場合のみ WDK とドライバ署名が必要になる
- DNS だけでは回避可能である前提を設計に織り込む。「DNS が通れば安全」とは考えない
- DNS レイヤも WFP レイヤも Policy Engine を呼ぶだけで、判定ロジックは持たない（ADR-0001）

## 注意

- DNS 設定を `127.0.0.1` に差し替えても、**後から増えたインターフェース**
  （VPN・テザリング・新しい Wi-Fi アダプタ）は元の DNS のまま残る。
  定期再適用または NRPT による固定を検討する（ARCHITECTURE.md §7-7）
- ローカル DNS プロキシの UDP 53 バインドとサービス登録には管理者昇格が必要
